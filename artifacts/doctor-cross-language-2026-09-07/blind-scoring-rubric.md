# 盲测独立判分口径

固定日期：2026-09-07。此口径在审查 `blind-result.json` 及本次运行的抓取来源之前制定。判分依据为独立准备的 `blind-ground-truth.json`、冻结代码、实际运行结果和实际提供给验证模型的文档。不会为使结果通过而修改冻结算法、输入或标准答案；如发现标准答案自身有错误，须另列更正及证据，并同时说明更正前后的影响。

## 1. 评估单位与基本原则

- 正例为 4 位医生的姓名、机构、科室三个维度各取中文或英文的全部 32 个组合。每个组合独立列一行，保留原 `case_id`。
- 输入中的中文测试音译不是官方译名。以合理音译能否对应同一真实人物判定，不能因输出采用另一合理音译就判错，也不能因模型声称两种姓名相同就判对。
- 机构可以是医院或大学。医院、大学、附属研究所、同名异地医院和不同院区须区分；只有有证据的父子机构关系、同一机构别称或并行任职可按标准答案中的对应关系认可。
- 科室翻译、上下级组织名称及医学专科可存在合理对应；必须注明是相同科室、上级部门还是专科描述。研究疾病、论文主题、参加某学科学会活动不自动构成该科室任职。
- 系统安全弃答与找到正确医生是不同结果。正例返回 `not_found`、无明确匹配的 `ambiguous` 或执行失败，均不算正例通过。
- 评估检索/验证系统实际交付的身份结论。规划阶段猜对名字、搜索结果出现正确人物、完整抓取页面中存在正确答案，都只能作为诊断信息，不能替代最终得到证据支持的匹配。
- 一个结果同时返回正确人物和错误人物或错误机构关联时，不作为完整通过；逐条记录正确条目与错误条目，不能只挑最好的一条计算成功。

## 2. 三个主指标必须分开

| 指标 | 定义 | 不可替代的含义 |
| --- | --- | --- |
| 程序 `matched` | 实际结果的 `verification.status` 为 `matched` | 只说明程序接受了模型输出，不说明事实正确 |
| 独立身份正确 | 最终明确匹配指向标准答案中的同一真实医生，且没有混入另一人物 | 可以姓名认对但机构、科室、证据或任职时态错误 |
| 完全符合契约 | 有完成的正例验证结论；人物、请求机构和科室均正确；引用真实且支持关联；来源类型、现任/曾任/不明及期间表述合理；无不受支持的附加匹配 | 这是严格正例通过指标，不能由程序状态或姓名正确率代替 |

程序状态不是独立结论的依据。某条 `matched` 如姓名、机构或任职推断错误，应明确计为错误或不充分。程序将正确证据拒绝为 `not_found` 时，可另标“检索到正确证据但验证未通过”，严格正例分子仍为 0。

三项主指标以全部 32 个预定正例为分母，同时另报各自的计数。无结论、缺失和未执行不从正例分母中删除。可补充“已完成验证中的准确率”，但必须显示较小分母，不能替代 32 项的完成率和通过率。

若正例验证已完成，随后负对照失败导致顶层 `error`，保留并独立审查已完成的正例结论，同时标记整次用例运行不完整；不能把失败的负对照算通过。若错误发生在正例验证形成前，正例严格通过记 0。

## 3. 每个正例的独立评分字段

| 字段 | 取值与判定 |
| --- | --- |
| `execution_status` | `completed` / `positive_completed_control_error` / `error_before_positive_verification` / `missing` / `not_executed` |
| `program_status` | 原样记录 `matched` / `not_found` / `ambiguous`；不存在则记 `null` |
| `name_correct` | `yes` / `no` / `uncertain` / `not_asserted`。匹配真实人物，允许合理姓名顺序、附加中间名及经核实的音译；同名者或不相容音译记 `no` |
| `institution_correct` | `yes` / `no` / `uncertain` / `not_asserted`，另标 `exact` / `equivalent_name` / `documented_parent_child` / `concurrent_but_distinct`。并行任职不能自动将一个机构替换为另一个 |
| `department_correct` | `yes` / `no` / `uncertain` / `not_asserted`，说明正式科室、分支/上级部门或专科间的可接受对应；无关专科记 `no` |
| `quotation_authenticity` | `verbatim` / `whitespace_normalized` / `altered` / `absent` / `unverifiable`，逐个检查四类引文 |
| `quotation_support` | `supports_relationship` / `mentions_only` / `contradicts` / `insufficient`，逐条解释是否真正连接此人、此机构和此科室 |
| `source_classification` | `supported` / `misclassified` / `uncertain`，依据页面性质判断，不照抄模型的 `source_type` |
| `temporal_assessment` | `reasonable_current` / `reasonable_former` / `reasonable_unclear` / `unsupported_current` / `unsupported_former` / `wrong_period` / `not_assessable` |
| `independent_identity_correct` | 只在最终明确匹配的全部人物均为正确身份时为 `true`；未给出身份不计入成功分子，可保留 `null` 说明没有身份断言 |
| `full_contract_pass` | 布尔值。上述必需维度全部满足才为 `true`；不明、缺失或未完成不算通过 |
| `failure_reasons` | 可多选：执行、规划、检索、选源、抓取、截取、机械拒绝、身份、机构、科室、引文、来源类型、任职时态、额外错误匹配 |

`name_correct = yes` 但引用不足时，可以报告“独立看来认对了人物，但不符合证据契约”。反之，四个字符串在原文中出现也不能弥补人物或机构关联错误。

## 4. 引文、来源及关联验证

1. 根据结果中的来源编号、URL、内容哈希与实际保存的来源文件对齐。缺失或无法对应的来源记不可核验，不凭搜索摘要或模型解释补证。
2. 分别核对 `person_quote`、`institution_quote`、`department_quote`、`affiliation_quote`。引文须是来源中的连续文本；仅折叠抓取排版带来的空白可单独认可为 `whitespace_normalized`。改变词语、大小写以外的实际拼写、标点关系、补词或拼接不连续片段，均须标出，不能当作严格逐字引用。大小写或兼容字符发生变化也须记录为文字变动，不能仅依赖代码的大小写/NFKC 归一化来宣称逐字相同。
3. 四个引文分别出现不等于关联成立。须检查姓名是此页主体还是其他被提及者，机构是否只是网站导航/页脚/另一人的履历，科室是否属于此人，以及关联句是否确实连接三者。
4. 按冻结实现的契约，至少一份被返回为匹配的文档应支持姓名、目标机构、科室及其关系。可用其他可靠一手资料确认真实身份，但不能将模型未见到的补充资料追认为本次输出已满足引文契约。
5. 区分完整抓取文本与实际送给验证模型的截取文本。必要时用冻结的 `sourceExcerpt` 重建输入窗口。完整文本有证据但窗口没有时，记录为截取/可见证据问题；不能算模型已经据此正确核验。
6. 医院/大学个人介绍、官方团队页及专业组织的个人介绍通常可作为一手身份来源。官方名册可用于核实登记关系和科室层级，但若只有姓名列表或电话簿式片段、没有足够个人关联，不自动满足个人介绍/关联证据要求。商业目录、作者机构列表、搜索摘要及模型记忆不能单独构成严格通过。
7. 独立标准答案可证明结论碰巧正确，也可证明其错误；不能消除本次返回证据不足的问题。所有补充核查需标为运行后独立核验，避免和模型实际检索到的证据混淆。
8. 三字中文姓名因代码的四字符引文门槛被拒绝时，记录“真实短引文被机械拒绝”。这属于实现导致的正例失败，不能将其解释为人物不存在，也不能手工改程序状态为通过。

## 5. 任职现状和时间

- 以 2026-09-07 为测试时点，并保留每个来源实际发布日期、明确更新日期及描述的任职期间。抓取日期、网页页脚年份、URL 目录年份、论文出版日期不能替代任职日期。
- `current` 需要实际来源对现任关系提供有时效依据的支持，并且没有已知更晚相反证据。2026 年有明确日期的官方人员/岗位记录可以支持“截至该记录时为现任”；不能把它扩大为未经限定的具体入职日或保证截至测试当日仍未变化。
- 根据冻结提示的明确要求，仅有无日期页面不能推断现任。无日期官方个人页可支持人物和机构/科室关联，`unclear` 通常是合理时态；因此没有 `current` 并不自动导致身份匹配失败。
- `former` 应有已结束任职、离任、退休、培训结束或明确历史岗位的证据。旧页面只说明当时的关系，不能仅因页面旧就断言现在“曾任且已离职”。
- 原输入没有指定年份，冻结契约允许明确标注为历史关系的匹配。真实且有来源支持的历史身份关联可被认可，但不能误报现职；另行显示其是否符合标准答案中记录的当前关系。
- 入职、取得学位、专科认证、执照注册、职称晋升、开始领导岗位和公司授权的日期分别核对。不得互相代用。
- 并行的临床任职、大学学术任职和研究职位分别核对。旧副职/助理教授称谓与新主任/副教授称谓冲突时，记录来源时间与适用职位；不能拼成一个虚构现职。
- 论文作者单位只说明论文所报告的机构归属，不独立证明当前任职。研究主题、合作机构及培训地点同样不能自动变成现职。
- 不确定性合理且明确标注时，可以通过时态契约；无证据地精确断言现职或期间，记为时态错误，即使人物身份本身正确。

## 6. 负对照

冻结 runner 仅在 4 个全英文正例之后分别执行两个验证阶段负对照：把机构替换为 `Unrelated Example Hospital 9XYZ`，或把科室替换为 `Ophthalmology`，复用原正例的文档。预定上限为 8 个负对照；它们不检验新请求的完整检索流程。

每个负对照分别记录：

- `applicability`：`applicable` / `not_applicable` / `uncertain`，并说明依据。若医生确有可使眼科输入成立的科室任职或等价临床关联，眼科负对照标不适用；偶尔研究眼部疾病、合作论文或同页出现眼科词，不自动构成眼科任职。
- `execution`：`completed` / `error` / `missing` / `not_executed`。要求实际存在对应的修改后 `doctor`、验证调用和结果；不能从父正例的状态推断负对照已经运行。
- `evidence_challenge`：`informative` / `uninformative` / `unverifiable`。验证模型确有足够辨识原人物及其机构/专科的材料时才构成有信息的辨别测试；空文档或完全无关文档导致的弃答须单列，不能宣称证明了机构/科室辨别能力。
- `outcome`：`definitive_correct_rejection` / `safe_ambiguous_abstention` / `false_acceptance` / `not_applicable` / `not_scored`。

判定规则：

1. 适用、实际完成、有信息的负对照，返回 `not_found` 且没有被接受的错误匹配，理由与机构/科室不符相容，才计为严格正确拒绝。
2. `ambiguous` 且没有错误接受可记为安全弃答，但与明确正确拒绝分开统计，不计入严格负对照通过分子。
3. 返回 `matched` 并认同被替换的错误机构或科室，或在其他状态中保留错误的肯定匹配，记为错误接受。仍认回原始机构/科室却忽略修改后的请求，也不算负对照通过。
4. 未执行、缺失、执行报错、证据不可核验或空文档导致的无信息拒绝，均不算通过。
5. 不适用负对照从“适用负对照准确率”分母中单独剔除，同时公开不适用数量和理由；不把它计作成功。适用性不明须保留为待定，不能默认为通过。
6. 同时报告预定 8 项中的执行覆盖数、适用数、有信息数、明确正确拒绝数、安全弃答数、错误接受数和未评分数。所有比率注明分母；不能把“没有看到错误接受”等同于“全部负对照通过”。

## 7. 汇总与诊断报告

- 提供 32 个正例的逐例评分表，并汇总程序 `matched`、独立身份正确、完整契约通过、错误/缺失、错误肯定匹配和任职时态错误的数量。
- 按医生以及 8 种语言组合分别汇总，列出全英文基线与各混合输入的变化。只做这 4 人的小样本描述，不据此估计全球医生或所有文字系统的普遍成功率。
- 负对照提供独立的逐项表，不混入 32 个正例的分母。
- 错误可按规划、检索、选源、抓取、截取、机械验证、模型语义判断及时态推断定位，但诊断不改变严格通过口径。
- 记录共享文档缓存及失败 Promise 缓存造成的相关性，比较延迟时区分缓存命中。不得把 32 项视为独立网络重复试验。
- 引用静态审计中保留的专科词排序偏置、跨文字支持限制及机械核验缺口。冻结版本的整文件哈希才标识本次被测实现；结果中的局部提示词哈希不能替代它。
- 所有争议项保留原始模型响应、机械拒绝原因及必要短引文。证据不足时给出“不确定/不符合契约”，不为提高命中率推断缺失事实。
