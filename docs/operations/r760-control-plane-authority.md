# R760 Gateway Control-Plane Authority

Last updated: 2026-08-06

## Authority boundary

R760 is the authoritative endpoint for these operations:

- real-user `cgu_live_*` issuance;
- user enable/disable and credential revoke/update;
- plan and entitlement changes;
- current and historical Gateway usage queries.

Azure `https://gw.instmarket.com.au` remains online only for clients that have
not yet changed URL. During that compatibility window, do not make direct
control-plane writes on Azure. R760 control rows are mirrored to Azure so both
old and new endpoints accept the same valid keys. Usage generated by old Azure
traffic is merged back into R760 by immutable request/reservation identifiers.

```text
control writes: operator -> R760 authority -> Azure compatibility mirror
usage history:  Azure compatibility events -> R760 authority
```

The two directions serve different purposes and must not be reversed casually.
Never copy either complete SQLite database over the other.

## Real-user key issuance

Use only the formal issue script:

```powershell
python scripts\issue-real-user-cgu-key.py --name "<real name>" --phone "<phone>"
```

It performs R760 create, R760-to-Azure control-state mirror, public validation
on both endpoints, and only then writes the R760-address handoff file. It fails
closed before handoff if the mirror or either endpoint validation fails.

The historical `issue-desktop-e2e-opaque-key.ps1` now also defaults to R760,
but remains a diagnostic/E2E helper and is not approved for real-user delivery.
`provision-medevidence-codex-key.ps1` is a legacy `cmev1` recovery tool for the
Azure compatibility stack; it is not an authority path.

## User, credential, plan and entitlement writes

Use the safe wrapper. It executes the approved admin command on R760 and then
creates a verified Azure backup before mirroring the resulting control state:

```powershell
python scripts\manage-r760-gateway-control.py --what-if -- disable-user <user>
python scripts\manage-r760-gateway-control.py -- disable-user <user>
python scripts\manage-r760-gateway-control.py -- enable-user <user>
python scripts\manage-r760-gateway-control.py -- revoke <credential-prefix>
python scripts\manage-r760-gateway-control.py -- plan deprecate <plan-id>
python scripts\manage-r760-gateway-control.py -- entitlement cancel <entitlement-id>
```

The wrapper intentionally rejects commands that issue, reveal or rotate
credentials. Use the formal issue workflow for deliverable keys. If an R760
write succeeds but the compatibility mirror fails, do not repeat the write;
run the read-only mirror plan and reconcile the already-written state.

For an independently made, approved R760 control change, reconcile explicitly:

```powershell
python scripts\sync-r760-azure-gateway-state.py
python scripts\sync-r760-azure-gateway-state.py --apply
python scripts\sync-r760-azure-gateway-state.py --fail-on-drift
```

`sync-azure-r760-gateway-state.py` is retained only for an explicitly approved
rollback or recovery. It is no longer the normal control-write direction.

## Usage authority and reports

New R760 traffic writes usage directly to R760. Old clients still create usage
on Azure, so merge the compatibility interval before an authoritative report
or the final Azure shutdown:

```powershell
python scripts\sync-azure-r760-gateway-usage.py
python scripts\sync-azure-r760-gateway-usage.py --apply
python scripts\sync-azure-r760-gateway-usage.py --fail-on-drift
```

The merge uses one fixed `[since, until)` window per run. It imports request
events, finalized token reservations and admin audit rows idempotently, and
updates token windows only by the inserted/finalized delta. Existing rows are
not counted twice. Schema, encryption-secret digest, SQLite integrity, foreign
keys, immutable conflicts, control-row dependencies and open reservations are
checked before writes. A verified R760 backup is mandatory when changes exist.

The default lower bound is `2026-08-04T00:00:00.000Z`. Override `--since` only
when an earlier compatibility interval has been reviewed. Open reservations
are never imported; wait for them to finalize or investigate them separately.

Run the R760 daily report after the merge:

```powershell
python scripts\check-daily-usage-health.py --format json
```

No periodic reconciliation job is planned because Azure is temporary. Until
the old endpoint stops receiving traffic, the operator must run the usage merge
before any authoritative usage answer and once more after Azure is frozen.

## Client-message queries

The message-query helper defaults to R760. Old clients may still upload their
diagnostic events only to Azure, so use the explicit compatibility preset when
investigating one of those clients:

```powershell
python scripts\query-client-messages.py --user "<user>" --limit 20
python scripts\query-client-messages.py --azure-compatibility --user "<user>" --limit 20
```

Client-message storage is support telemetry, not part of the authoritative
plan or token-usage ledger.

## Azure shutdown gate for this domain

Before stopping the Azure Gateway:

1. freeze or block new Azure Gateway writes and confirm open reservations are zero;
2. run the final Azure-to-R760 usage merge and require a second dry-run with
   `changed_rows: 0`;
3. run the R760-to-Azure control dry-run and require `changed_rows: 0`;
4. validate representative historical and newly issued keys on R760;
5. archive both final SQLite databases and their SHA-256/integrity evidence;
6. only then remove the temporary Azure compatibility requirement from the
   issue and management workflows.

This gate covers Gateway control and usage data only. The other Azure-hosted
services in the VM retirement inventory have separate migration/retirement
gates.
