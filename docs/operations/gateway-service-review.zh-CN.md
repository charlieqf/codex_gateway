# Gateway 12/24 小时服务巡检

在主工作区 `C:\work\code\codex-gateway` 执行现成的只读命令：

```powershell
python scripts/check-daily-usage-health.py --hours 12 --timezone Asia/Shanghai --format json
```

24 小时只改为 `--hours 24`。省略 `--format json` 可显示文本报告。
`--hours` 与 `--date` 互斥；不传这两个参数时沿用当日统计，默认时区为
Australia/Sydney，国内运维应显式传入 Asia/Shanghai。

## 固定检查范围

- 公网和本机健康、TLS、容器状态、OOM/重启计数、磁盘、内存和系统服务。
- 指定时间窗口的请求事件、用量、错误码、额度限制类型。
- 当前运行快照、正在执行的请求告警，以及快照内近期的超时和上游异常。

先返回固定摘要，再按报告中的异常定位请求 ID 或窄时间段。不要每次复制、
修改 `.task-artifacts` 中的历史采集器，也不要把巡检变成全库备份、完整性扫描、
全量客户端会话读取或无关功能自测。只读巡检不需要部署或重启。

## 统计与结论边界

- 窗口按请求 `started_at` 筛选，包含测试流量和非模型接口事件；总事件数不能
  写成模型调用量，也不能直接写成真实用户模型成功率。需要业务口径时再按
  模型、已确认测试身份和最终结果细分，不凭名字包含“测试”批量排除用户。
- 报告的时间窗口与运行快照中的 `15m` 等窗口分别解释，不能混用。
- HTTP 200 不保证流内成功；结合最终请求状态和上游尝试判断。客户端取消、
  Gateway 分钟/日额度限制、上游错误后恢复成功、发布探针分别说明。
- 健康检查和重启计数是当前容器的状态。重建容器会重置计数，不能据此断言
  整个 12/24 小时没有中断。只有出现相关异常或需核实可用率时，再查边缘日志
  和发布记录；计划内发布中断仍需计入实际可用性说明。
- 报告缺失组件或采集报错时明确标记未知，不能将缺少数据解释为正常。
- 磁盘百分比按 `used / (used + available)` 计算，和 `df` 使用同一分母，
  不把 ext4 预留块算作可用空间；`df` 的整数向上取整与报告的一位小数略有差异。
- 脚本可返回用户身份信息，原始 JSON 留在受保护的本机目录；对外只给必要
  聚合和脱敏证据，不提交原始用户报告。

2026-11-13 验证：滚动窗口改动的 9 项单元测试通过；线上只读 12/24 小时检查分别为
8.65/9.48 秒，无采集错误。后续修正预留磁盘块口径后共 10 项测试通过，线上复核
正确报告根盘 86.4% 告警，无采集错误。耗时为当次测量值，不是固定性能承诺。
