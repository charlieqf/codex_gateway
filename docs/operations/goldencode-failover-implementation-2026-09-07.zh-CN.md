## 实现范围

`goldencode` 的腾讯／天宽文本池新增原生工具故障切换，覆盖 Chat Completions 与 Responses、
流式与非流式。首选仍按原 HRW 粘性策略选择；备选经过成员启用状态、冷却和并发容量检查。
未引入第三供应商。xAI 视觉、本地模型、图片与 Research 不进入本次新增路径。

- 上游 HTTP 402、408、429、5xx，或响应头前的网络故障可以切换。
- Gateway 本身的套餐／认证／限流，以及供应商 400、401、403、404、上下文问题、截断、
  策略拒绝、已生成内容／工具片段后的失败，不进入新增跨供应商重试。
- 一个原生请求的初次生成、工具参数修复、跨平台重试共享两次实际调用预算。
  原平台已修复一次，则没有第三次跨平台调用；切换后也不能再发起第三次修复。
- 共用原请求 AbortSignal 与截止时间；取消、连接关闭、已交付业务输出或剩余不足一秒时不再切换。
  失败后先释放原 lease；最终 lease、用量预留和客户端并发由既有请求 finally 清理。
- 客户端只接收最终校验通过的工具结果；本地工具副作用仍由客户端负责。
- 成功请求顶层采用最终成功状态，历史错误保留在 attempts。两次已知 usage 合计用于响应与结算，
  不再被最后一次 usage 覆盖。缺失 usage 保留 null，沿用现有缺失用量策略，不伪造上游实测值。
- 普通文本成功摘要采用同样的终态与用量汇总；在目标灰度范围使用同一切换错误筛选规则。
- 错误响应从批准的响应头或 JSON 顶层 `request_id` 提取供应商编号，限制字符、长度并排除密钥。
  保存 HTTP 状态与响应哈希／长度，不把完整错误响应或供应商密钥放进客户端响应。

## 启动配置

配置在 Gateway 启动时读取，不支持热更新。下表是已实现的配置契约，不是生产当前值。

| 变量 | 默认 | 契约 |
| --- | --- | --- |
| `GATEWAY_GOLDENCODE_NATIVE_FAILOVER_MODE` | `disabled` | `disabled` 或 `enforce`；启用目标池原生切换，并统一该范围普通文本的错误筛选 |
| `GATEWAY_GOLDENCODE_FAILOVER_SUBJECT_IDS` | 空 | 逗号分隔的内部 subject ID；非空时只对名单内用户启用上述功能，空表示目标池全量；逗号之间或末尾的空项会导致启动报错；只有 mode=enforce 才有效 |
| `GATEWAY_GOLDENCODE_QUOTA_COOLDOWN_SECONDS` | `0` | 0 关闭 P1；1–86400 秒启用目标池的共享额度冷却；建议首次受控验证用 300 秒 |

P0 回退为 disabled 会恢复原生旧路径；原来已存在的普通文本重试仍存在。
P1 独立控制整个目标池的供应商健康状态，不受用户灰度名单限制，不能把 P1 全池启用称作用户灰度。
只部署代码、保持默认关闭，不会启用新增切换和额度冷却。

## 额度恢复语义

额度状态按进程内成员／账户维护。供应商 402 打开冷却；记录失败请求的输入估算量和最大输出预算。
参数修复增加的实际请求预算也会更新记录。未提供输出预算的目标原生请求显式发送模型配置的
最大输出预算，避免用供应商隐式默认值作为恢复证明。

冷却到期仅允许一个输入与最大输出预算都不低于失败记录的真实业务请求进入恢复探测。
256-token 小请求不能解除 8192/128000-token 故障。探测完整成功后恢复流量；探测失败、取消或
释放时再次冷却。代次与探测持有者检查可阻止旧请求的晚到成功解除新故障，也避免并发探测。
如果没有足够预算的业务请求，保持冷却，不主动制造收费探测流量。

这是进程内第一版：没有跨重启持久化，也不协调多个 Gateway 实例。重启会清空额度冷却；
运营主动禁用的 `enabled=false` 在配置中保留，不受重启或探测影响。需要多实例或跨重启冷却时，
必须另行扩展共享状态，不能按已具备此能力上线。

日志 `Provider quota circuit state changed.` 包含成员 ID、closed/open/half_open、代次、截止时间和
预算形状；`Native tool provider failover assessed.` 包含 Gateway request ID、来源／目标、分类、
已用调用数及备选不可用原因。请求 events/attempts 保留最终与历史结果，供现有运维查询关联。

## 客户端配合

客户端继续使用 `goldencode`，不自行切换供应商。一次请求内等待 Gateway 的最终成功或失败，
不把内部失败尝试展示成最终报错。取消应中止 HTTP 请求，终态后不得重新启动同一轮。
客户端总超时应覆盖 Gateway 总超时与合理的传输余量；不要为每个供应商分别重置计时。

收到完整有效的工具调用后才执行本地 Shell/write，按 turn/tool-call ID 防止重复执行。
部分输出、工具已执行后的连接失败不能盲目重放整个 turn；保留已完成工具结果再恢复模型请求。
供应商故障、用户密钥拒绝、上下文溢出和本地工具失败应分别显示与诊断。记录客户端版本、
turn/session/message/tool-call ID、Gateway request ID、取消／超时来源和是否已执行业务副作用。
具体协作清单沿用[实施方案客户端章节](./goldencode-tencent-tiankuan-failover-implementation-plan-2026-09-07.zh-CN.md)。

## 实施后自审

2026-09-07 按用户要求检查过度抽象、防御性代码和兜底，并直接修正：

| 发现 | 修正 |
| --- | --- |
| 缺失额度请求形状被填成 `Number.MAX_SAFE_INTEGER`，会把内部接线错误变成几乎不可恢复的冷却 | `QuotaTicket.shape` 改为必填；启用额度策略却不提供预算时直接报错，不获取 lease |
| 所有真实 lease 都实现 `recordOutcome`，接口仍将其声明为可选，并在 dispatcher 回落到 router 方法 | 改为必选方法，删除兼容分支和多余的 router 参数 |
| 未分类工具错误通过 `recordSuccess` 清除上游健康状态，随后又用 `updateQuotaRequest` 方法是否存在来规避该行为 | 删除错误路径转健康成功的兜底，直接记录可分类错误；未分类错误不冒充成功 |
| 历史摘要通过标志、重复检查和再次追加当前错误来合并，调用者已经完成一次入列 | 每次实际执行只入列一次，统一保留 attempts 原结果；合并取消／截止判断的重复代码 |
| 灰度名单静默过滤空项，逗号组成的非空配置会变成空名单并扩大到全量 | 明确拒绝空项，合法空配置与损坏名单不混同 |
| 在 `GatewayError` 对象上动态挂载响应摘要；错误体读取失败被视为真实空响应并生成哈希 | 返回明确的 `{ error, responseSummary }`；读取失败保留 HTTP 状态，哈希和长度为 null |

保留的抽象有实际复用或状态职责：调用预算协调初始生成、参数修复和跨平台切换；额度状态机隔离
代次和单探测；成功摘要函数由原生、普通文本流式及非流式共用。没有继续扩展成通用重试框架。
原生专用字段移到原生输入接口，避免污染严格工具输入。

保留调用前后取消检查、两次硬上限、重复释放保护、旧探测结果防护和错误编号脱敏：这些对应已验证的
取消竞态、重复工具风险、并发容量和敏感信息边界，不属于无依据的防御。
错误体无法读取时仍依据已收到的 HTTP 状态处理，是有明确依据的诊断降级；不伪造响应内容。

自审后验证：8 个相关测试文件、364 项全部通过；`npm run typecheck` 和 `git diff --check` 通过。
此轮未改生产配置或部署代码，线上仍仅启用腾讯，天宽等待明确恢复指令。
