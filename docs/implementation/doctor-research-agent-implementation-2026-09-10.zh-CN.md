状态：实施中，未部署。目标仍是合理划分 Agent 与固定代码职责，并让所有已知医生案例在没有案例专用预置的情况下完成服务请求；目前没有达到该目标。本文承接[整体设计审查](doctor-research-design-review-2026-09-10.zh-CN.md)。

2026-09-11 更新：已贯通身份之后的资料、本人文献和领域文献调查；详见[后续实施记录](doctor-research-evidence-agent-2026-09-11.zh-CN.md)。本文下方的 2026-09-10 结果保留为历史快照，不代表最新代码仍仅覆盖身份。

## 当前实现

新增 `identity-investigator.ts`，由模型选择搜索、阅读正文、分页查看真实链接、继续补证或提交身份结论。用户输入的机构和科室约束最终身份，不再被代码固定拼成每一条查询。搜索候选不会因标题没有完整姓名或不属于已收录机构而被提前排除。

固定代码负责公开 HTTPS 抓取、链接来源、资源上限、引用片段存在性、状态保存和租约隔离；独立模型复核人物关系、机构和科室对应。页面保留表格行、人员条目及段落边界。身份结论必须有来源片段，不能仅凭模型判断或关键词共现放行。

Agent 的搜索、页面和模型调用在执行前保存资源预留，成功搜索与已读取页面可在同一任务恢复时复用。SQLite 增加可替换的 Agent 状态接口，独立于原有不可变阶段检查点；旧 Worker 无法写入新租约的状态。尚未完成文献与生成阶段的整体恢复改造。

试验开关为 `RESEARCH_IDENTITY_AGENT_ENABLED`，默认关闭。启用时 Worker 使用新流程，Gateway 停止加载和注入医生预置注册表；调用方主动提交的资料仍按接口规则处理。Agent 模型调用另计预算；当前默认身份预算为 4 次搜索、12 次页面请求和 8 次模型调用，不能通过只启用开关绕过预算检查。准备度接口的可表达调用上限扩至 32，真实服务权益检查仍保留。

新增 `resource_budget_exceeded`，用于区别资源耗尽与身份没有被核实、模型格式错误或任务超时。尚未完成全部客户端契约文档及错误状态验收。

### 第一例真实联网身份验证

[输入与完整结果](../../artifacts/doctor-research-agent-2026-09-10/live-canary2/result.json)：

- 输入：Shoshana Sztal-Mazer / 阿尔弗雷德医院 / 内分泌科。只使用此前保留的原始三字段。
- 结果：身份确认；**43.978 秒，1 次 SerpAPI 请求，5 次模型调用，读取 1 个页面**。
- Agent 自行生成英文查询并读取 [Endocrinology Clinic](https://www.alfredhealth.org.au/services/endocrinology-clinic)，以人员名单、科室和 The Alfred 联系地址建立对应。
- 第一次结论有引用片段不完全匹配，固定代码拒绝；Agent 改用真实原文后通过独立复核，没有追加搜索。
- 未传入主页、机构别名、答案、历史报告或核验真值。应用无身份缓存，供应商请求设 `no_cache=true`。旧预置发现方法被替换成抛错哨兵，实际调用为 0。
- [冻结清单](../../artifacts/doctor-research-agent-2026-09-10/live-canary2/manifest.json)确认输入和代码哈希、结束码 0、执行前后代码不变；[状态记录](../../artifacts/doctor-research-agent-2026-09-10/live-canary2/state.json)保留查询、候选、正文和补正过程。

这是身份子流程的联网验证，不包含 API 准入、排队、本人文献、报告生成或产物下载，因此不能把 44 秒直接当作完整服务耗时合格，也不能由此宣称其余案例全部通过。

第一次试验容器 `live-canary1` 因启动器缺少 `orcid` 配置在构造适配器时退出，未开始搜索或模型调用。修复的是启动器配置，第二次保持同一输入和研究内核；这次启动失败保留在[试验历史](../../artifacts/doctor-research-agent-2026-09-10/probe-history.json)，没有当作医生搜索失败或静默丢弃。

## 搜索额度与时间要求

2026-09-10 13:34:58 UTC 的账户查询返回剩余 47 次，本轮之后已实际使用 1 次。账户查询本身不计入搜索额度，依据 [SerpAPI Account API](https://serpapi.com/account-api)。不把这一余额视为可以全部用于测试。

第一例联网试验有 2 次实际搜索请求硬上限，失败请求也先预留计数。后续批次仍需先固定整批上限，包含所有内部重试和重新调度；暂未启动其他医生的联网批测。

完整服务验收继续采用：≤5 分钟优秀，5–8 分钟可接受，超过 8 分钟调查原因。研究正确且内容满足请求是前提；快速失败、缺失报告或只完成身份核验不计为完整成功。

## 剩余必做工作

1. 文献发现和作者归属仍经过原固定查询/匹配逻辑，包含病例相关机构译名依赖；需让 Agent 根据证据制定和调整查询，区分缺元数据与明确不匹配。
2. 履历提取仍有固定词语类型判断和姓名窗口匹配；需改为有来源依据的人物事实核验，不能在身份通过后重新拼错人物。
3. 完整研究状态、生成修复、真实歧义和预算终态需要贯通；当前恢复改造主要覆盖身份阶段。
4. 明确 brief 与研究报告的交付契约，完成错误码及客户端兼容文档，避免降级质量后宣称全功能成功。
5. 修复并完成整体回归，保留反例。六个原截图案例、王永生和八个已揭示案例都仍需最终版本的完整服务验收；已有历史回归用例也不能丢失。
6. 固定运行代码与公共数据版本，再用原始三字段执行限额验收并核查内容及产物。不得把本轮访问到的资料制作成案例预置后声称通用成功。符合要求后再按运行手册部署、验证和清理试验资源。
