# Doctor Research：医生资料检索的交付范围调整

2026-09-11 用户明确：搜索产出物不要求很高的学术性，这不是文献评审任务，并同意按照本文思路简化。新流程已在隔离工作树实现，尚未上线；旧合同隔离探针继续保留为历史诊断证据。

## 实现与启用边界

- 新增独立的 `practical-profile-agent.ts` 与 `practical-profile-output.ts`。身份 Agent 成功后，资料 Agent 可选读取实际发现的页面或 PubMed，提交简短资料；事实编辑可直接修正或删除不受支持的可选内容并批准。最多 6 次资料/编辑调用，加身份最多 8 次，总上限 14 次。正常已有资料时，资料阶段只需整理和编辑两次调用。
- 来源使用实际已读内容的片段编号。固定代码负责来源存在性、预算、恢复、结构与四文件完整性；跨语言身份、岗位含义和事实归属由 Agent 判断。默认不执行学术长文生成、领域论文扩展、逐篇方法表或最低字数核验。
- 四个 `kind` 和 ASCII 下载名保持不变，UTF-8 文件名采用“公开资料”“专业背景与交流准备”“交流问题”“参考要点”。JSON 协议版本保留 v1，允许空文献来源和检索式；没有论文不是质量警告或失败条件。原检索输入与核实事实分别显示。
- `RESEARCH_IDENTITY_AGENT_ENABLED=true` 时新流程默认启用；可显式设置 `RESEARCH_PRACTICAL_PROFILE_ENABLED=false` 保留旧学术流程用于对照。生产当前身份 Agent 开关未切换，部署时须显式启用身份 Agent，并将模型调用预算设为 14；资料阶段输出上限 6000 token，旧学术 minimum 配置不参与新流程内容校验。
- Skill 版本 1.7.0、工作流 v89、提示 v34、校验 v49、产物策略 v4。创建任务与执行端同步升级；上线需处理旧版本在途任务，不能只换 Worker 让旧任务被版本门槛拒绝。
- 本地测试包括无论文的四文件交付、编辑删除无依据成果、来源编号错误批量反馈、可选论文查询超时、恢复时不重复成功搜索/读取、编辑中断后继续以及配置预算。脚本模型测试只证明流程机制，不证明模型对真实医生的事实判断。
- 真实案例通过情况以 `artifacts/doctor-research-agent-2026-09-10/known-case-acceptance.json` 及探针原始证据为准；新流程尚未完成全部 15 例和公网准入/排队验收。

## 判断

当前最主要的困难是交付范围过重。旧合同要求至少 5000 内容字/词、目标 6000、目标 40 篇参考文献、3–8 条含设计/样本/方法/结果/局限的核心证据，以及三段正文生成、来源分组核查和整稿循环复核。身份搜索成功后还会因引句、研究类型、段落字数或修改格式不能满足而整体失败。继续修复这条长链的边缘情况，不能代替纠正产品定位。

真实案例已证明跨语言识别并非不可实现。沈嵘和 Shoshana Sztal-Mazer 均有独立身份通过记录；最新国外案例读了 25 篇论文并通过证据复核后，还要执行完整学术报告生成与复核。搜索能返回结果，但长流程的后续要求扩大了耗时和失败机会。

第二类困难是 Agent 工具接口摩擦：逐字抄写引句、严格 JSON、滚动上下文、一次只报告首个校验问题，以及修改路径格式。来源片段编号、Agent 自选来源保留、批量错误反馈和局部修改属于可复用修复，适合保留。它们不应变成继续维持不必要学术流程的理由。

在当前 canary10 的第七次输出复核记录中，模型仍因 `449/450` 的主题段落字数诊断追加扩写，并给问题补数字引用；该轮调用耗时 50.276 秒。这轮也有其他校验工作，不能把全部 50 秒归给一个字，但这种交付门槛本身应从默认资料任务中取消。

第三类困难仍需处理：同名消歧、现任与历史任职、跨语言机构表达、页面访问失败，以及稀疏公开资料。降低篇幅或取消文献门槛不会自动解决这些问题，应由 Agent 结合实际来源判断并明确边界。

## 建议的默认交付

| 内容 | 默认要求 |
| --- | --- |
| 医生/专业人员资料 | 姓名、机构、科室/岗位、已核实职称、主要专业方向及简要经历；缺少的可选字段可省略 |
| 背景摘要 | 围绕本人工作，通常约 500–1000 字；以有用和简明为目标，不设学术字数硬门槛 |
| 代表成果 | 有可靠材料时列少量代表条目；通常最多 3–5 项，不强制查到论文，不分析每篇研究方法与统计数据 |
| 问题与参考要点 | 可保留现有 5 个问题及答案文件；提供背景要点/待确认点，不冒充本人意见 |
| 来源 | 保留实际阅读的公开来源链接；通常少量权威页面即可，不以数量判定完整性 |

四个产物的外部协议可保留，原“前沿综述”内容改为与本人相关的背景摘要，必要时同步调整界面名称。企业和学会人员按真实岗位整理，不强制构建临床研究方向。

建议默认流程：搜索与阅读 → Agent 整理资料和背景 → 一次有针对性的身份/重要事实来源核查 → 文件交付。仅在真实歧义、关键来源冲突或可恢复请求失败时追加调查。取消默认领域文献扩展、逐篇证据表、三段学术写作和论文式多轮复核。PubMed 查询作为代表成果确有需要时的可选工具。

## 成功与质量标准

确认本人并交付有来源的实用资料，即可成功。研究成果、教育经历或某个额外头衔未核实，不阻断已有可靠资料；在相应位置说明范围，不能把未知写成不存在。真正无法区分同名者时，应请求补充信息，不能选一个凑结果。

保留身份关系准确、重要事实有来源、引用未伪造、本人论文未冒认、工具失败如实分类、任务恢复及文件完整性。减少的是覆盖范围、分析深度与格式负担，不能凭空补全履历或放行错误归属。

保持用户的完整服务计时标准：≤300 秒优秀，≤480 秒可接受，>480 秒调查；计时含排队、重试和文件交付。结构缩短预计可减少模型调用、输入长度和搜索用量，具体改善幅度必须在相同原始医生案例上实测，当前不承诺尚未测得的耗时。

## 实现次序

1. 明确独立的实用资料合同，替换默认流程中的旧学术最低字数、参考文献数、核心证据与段落要求；提示、验证器和成功状态同步修改，不能只调一个字数参数。
2. 将代表论文查询改为可选；允许资料部分充分而可选信息缺失时正常交付，保留来源与限制。
3. 用单个负责整合资料的 Agent 和一次聚焦事实的复核替代三段学术生成及多层审阅；继续使用通用来源工具与恢复机制。
4. 先用已保存来源做零 SerpAPI 的机制检查，再用原始三字段逐个真实验收。明确区分回放与无预设案例，不因后续简化而倒签此前失败结果为成功。

原学术合同由仓库 `review-contract-policy.ts` 与旧业务 Skill 导出，不能仅修改文档就假定运行时已变。用户本次明确的产品定位应指导后续新合同；本次未修改或部署线上内容门槛。
