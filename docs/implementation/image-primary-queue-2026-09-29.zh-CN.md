# 生图固定模型与扩大等待容量

状态：`752221d` 已提交、推送，于 2026-09-29 05:20:41 UTC 上线，实际生图与公网自测通过，详见 [发布回执](../operations/image-primary-queue-release-2026-09-29.zh-CN.md)。本次保留生产密钥和业务数据，不修改客户端代码。

## 实现

- 在现有 `resolveImageGenerationBillingFallbacks` 入口增加 `MEDCODE_IMAGE_FALLBACK_ENABLED=0|1`。关闭时直接返回空列表，包括显式注入和配置文件来源；不读取后备密钥文件，也不删除密钥。Qwen 主模型默认关闭，其他主模型保留旧默认；生产部署显式设为 0，避免依赖默认值。未增加执行分支、重试循环、第二层队列或公平调度器。
- Qwen pool 保留现有 FIFO 与共享 GPU 调度，两个执行名额加十个等待名额；共享调度器的生图在途上限同时改为 12。实际并发仍由两个 worker、共享锁、CT 优先、内存和温度准入决定。未改变 CT 容量、协议或模型推理参数。
- pool 排队上限 600 秒、总期限 780 秒；调度器协议校验同步放宽。调度器实际执行仍最多 180 秒，pool 到 worker 的 HTTP 各阶段超时也限制在 180 秒以内（HTTPX 阶段超时不等于整个操作总期限）。总期限从首次接收请求开始，不因派发或控制调用重试刷新。
- Qwen provider 默认 790 秒、Qwen 主模型的 Gateway 总请求默认 810 秒。显式环境变量优先，部署必须替换生产仍配置的短期限。
- Gateway 停止排空默认由 600 改为 900 秒，Compose 停止宽限由 610 改为 910 秒；运维 drain 默认同步延长。pool graceful shutdown 改为 800 秒，systemd TimeoutStopSec 为 810 秒，发布/回滚工具等待该服务停止最多 830 秒，防止长队列请求仍在合法等待时被旧停止期限截断。

## 部署配置与顺序

1. 以测试、提交后的 main 构建不可变 Gateway 制品、Qwen 源码和共享调度器 wheel。核对实际运行版本，保留调度器现有 **11 GiB** 主机内存预留，禁止用部署工具旧默认覆盖它。
2. 受控关闭图片准入并等待在途工作结束，备份服务配置及调度器 SQLite。升级 pool 与 broker 的容量和协议，核对安装在相关 Python 环境中的共享包一致。不能只升级 pool，否则旧 broker 仍会限制 4 个在途任务并拒绝新期限。沿用已有维护/排空流程，不改锁或强行清空任务。
3. Gateway 受保护配置显式设置：

   ```dotenv
   MEDCODE_IMAGE_PRIMARY_PROVIDER=qwen
   MEDCODE_IMAGE_FALLBACK_ENABLED=0
   MEDCODE_IMAGE_QWEN_TIMEOUT_MS=790000
   MEDCODE_IMAGE_REQUEST_TIMEOUT_MS=810000
   ```

   Qwen 凭据、地址和 `medcode-image-default -> qwen-image-2.1` 映射沿用现有配置。后备密钥留存，关闭开关使其不参与执行。

4. Gateway 经排空后重建，核对运行环境差异仅为批准项。现有历史 cutover 脚本环境白名单不包含本次配置变化，不能直接执行后临时绕过断言。首次从 b03a0c5 升级时，显式给新 drain 工具 900 秒等待；新容器使用 910 秒停止宽限。
5. 2026-09-29 只读核实 R760 公网 Nginx `proxy_read_timeout` / `proxy_send_timeout` 均为 **3600 秒**，足以覆盖此预算；无须修改。其他入口仍需逐一确认。按已更新部署手册轮询公网就绪，不用单次即时探针判定回滚。
6. 开放入口前验证回退列表为空、pool health 的 queue_capacity=10、最多两个执行、实际在途容量 12、过期/取消不重发、临时测试数据清理。客户端按 [通知](../outbox/image-primary-queue-client-notice-2026-09-29.zh-CN.md) 配置 900 秒或更长等待；尚未升级/配置的 210 秒客户端不能获得长等待保证。

回退时也先排空；旧调度器无法接收新的 600/780 秒注册参数，必须协调回退 pool 和 broker，不能混用。保留调度器数据库与任务记录，不恢复旧数据库覆盖新工作。
