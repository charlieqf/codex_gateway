三、修复行为
沿用现有校验重试及共享预算，最多再请求一次，不新增恢复循环或配置开关。
  - 带说明前缀、模拟结果、多轮角色文本或截断 JSON：识别为 text_tool_protocol。
  - 纠正请求保留原始任务和真实工具结果，要求下一未完成步骤使用结构化 tool_calls。
    被拒绝的模拟结果不会加入重试上下文。
  - 第二次只有正文、空输出或文本序列化调用：仍返回错误，不再静默成功。
  - 已有真实调用：不重新生成这一批；丢弃伴随的伪协议正文。
  - 原有“整段仅为标记加完整 JSON 调用数组”的窄兼容路径保留，并继续校验声明及 schema。
  - 普通标记说明、明确请求的协议示例保留为正文，不自动执行示例。
  - 取消、超时、预算耗尽或输出已交付时不启动额外纠正；取消/超时后也不交付返回的调用。

失败契约：code=tool_call_validation_failed，failure_kind=text_tool_protocol，
recovery_owner=gateway，automatic_retry_allowed=false，transformed_retry_allowed=false，
recommended_action=report_protocol_error，并携带 request_id。
响应头尚未发出时 HTTP 502；已发出 SSE 头时按既有机制发终态错误帧。
接口测试验证早期 streaming/non-streaming 失败均为 502，事件状态为 error，正文不泄漏。
