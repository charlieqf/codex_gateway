# 人物研究服务输入字段对接方案

版本：对接方案 v1.0（服务端已发布）

日期：2026-10-12

面向：调用方产品、前后端及测试团队

状态：**本文新增字段及科室可选规则已于 2026-10-12 发布到线上，服务端版本 `088f11a`。旧请求继续兼容；调用方启用新字段时，仍须验证自身表单和结果解析，尤其是空科室。**

## 1. 本次调整

让现有 Doctor Research 支持医院医生、药企人员、国内外学会任职人员、大学及研究所人员。输入需区分“这个人是谁”和“这次想讨论什么”。

采用现有接口的增量扩展：

- `hospital` 保留字段名，界面改称“所属机构”，可填写医院、企业、学会、大学或研究所。
- `department` 改为可选，填写真实的“科室／部门／团队”；没有或不知道就不传。
- `title` 继续填写“职务／职称”，例如主任医师、首席医学官、理事、研究员。
- 只新增 `interview_topics`（采访主题）和 `interview_focus`（采访重点）。

一次请求填写一组姓名、所属机构及对应任职信息即可。不要求调用方增加身份选择、多任职录入或管理功能。

**疾病主题不等于科室，学会任职或企业职务也不代表临床执业身份。** 例如，在亚盛医药任职的人参与淋巴瘤采访，不能据此填写“淋巴瘤内科”。

## 2. 接口与兼容范围

创建路径继续使用：`POST /gateway/research/v1/doctor-runs`。

鉴权、幂等创建、任务轮询、取消和产物下载沿用已有协议。本文只定义输入扩展，不新增 v2 路径或请求体 `schema_version`。现有结果版本 `doctor_research_result.v1` 和技术字段名 `doctor` 保留。

| 项目 | 发布前接口 | 当前线上接口 |
| --- | --- | --- |
| `name`、`hospital` | 必填 | 仍必填 |
| `department` | 必填且非空 | 可省略或传 `null` |
| `title` | 可选 | 继续可选，承载职务／职称 |
| 采访主题、采访重点 | 无独立字段；传入会被拒绝 | 接受本文两个新增字段 |
| 原有合法请求 | 按现有协议处理 | 保持兼容，不强制补传新字段 |

当前接口仍拒绝未定义的字段。**没有科室时省略 `department` 或传 `null`，不要用“无”“不适用”、职务或疾病主题填充。**

本文示例统一把字段直接放在请求顶层。现有接口也支持将身份字段放在 `doctor` 对象内；仅供已采用该写法的调用方继续使用，无需迁移或新增支持。该写法下，两个新增采访字段仍放在请求顶层。

本次发布同时修正了旧版平铺写法携带 `language` 等通用字段时的重复校验问题。

## 3. 表单与字段定义

下表为当前线上字段规则。

| 表单名称 | API 字段 | 类型与限制 | 填写规则 |
| --- | --- | --- | --- |
| 姓名 | `name` | 字符串，2–100 字符；必填 | 本人姓名；外文人士优先填写原文全名 |
| 所属机构 | `hospital` | 字符串，1–200 字符；必填 | 本次采访登记的任职机构，优先全称 |
| 科室／部门／团队 | `department` | 字符串，1–200 字符；可选 | 真实组织单元；可包括科室、院系、研究室、课题组、学会分会或专业委员会 |
| 职务／职称 | `title` | 字符串，最多 100 字符；可选 | 如“科主任、主任医师”“理事”“研究员”；与所填机构对应 |
| 采访主题 | `interview_topics` | 字符串数组，1–3 项，每项 1–100 字符；API 可选 | 新表单必填；如“淋巴瘤”“肿瘤免疫治疗”。旧调用方可以不传 |
| 采访重点 | `interview_focus` | 字符串，最多 1000 字符；可选 | 说明关注的问题或受众，如“面向血液科医生，关注耐药机制与临床证据” |

填写规则：

1. 文本去除首尾空白。必填字段不能是空白字符串；可选文本无内容时省略或传 `null`，不传空字符串。
2. `interview_topics` 不使用时省略或传 `null`；提供时必须是非空数组，不含空白项或重复项。多主题按填写顺序表示优先级，总共仍生成 5 组学术问答，不是每个主题各 5 组。
3. `interview_focus` 补充主题，不能承载额外的任职身份或未经核实的人物事实。新表单先填主题，再填重点。
4. 不新增必填“人物类型”“机构类型”。调用方可自行用类型选项切换表单标签，但不要把这些未定义字段发送给接口。
5. 不确定的科室、职务留空，不从会议名称、疾病主题或机构类型自动推断。

原有 `city`、`orcid`、`official_profile_urls`、`literature_identity`、`mode`、`language`、`options`、`client_reference` 继续按原协议使用，不要求新增填写。其中：

- `official_profile_urls` 可提供最多 3 个官方介绍或任职来源链接，仍受服务端 HTTPS 和域名白名单限制，不能保证任意官网均可接入。
- `literature_identity` 保持原有用途，不用于填写第二任职，也不要求给企业或学会人员编造论文检索身份。
- `mode` 目前仅支持 `brief`；`language` 支持 `zh-CN`、`en`。

推荐表单提示：

> 所属机构和任职信息请按实际情况填写；疾病或研究议题请填写到“采访主题”。没有科室、部门或团队可留空。

## 4. 典型请求示例

以下示例只展示 JSON 正文，鉴权与幂等请求头沿用已有协议。除翟一帆案例沿用本次输入外，其他人名与机构均为虚构示意，不能用于真实人物研究验收；示例也不构成任职核验结果。

### 示例 1：医院医生，有真实科室

```json
{
  "name": "张明",
  "hospital": "示例市第一医院",
  "department": "血液内科",
  "title": "主任医师",
  "interview_topics": ["淋巴瘤", "CAR-T 治疗"],
  "interview_focus": "面向血液科医生，重点讨论复发难治患者的治疗证据与安全性管理。",
  "language": "zh-CN"
}
```

“血液内科”是实际科室；“淋巴瘤”和“CAR-T 治疗”是采访主题，两者分别填写。

### 示例 2：药企高管，没有可确认的部门

```json
{
  "name": "翟一帆",
  "hospital": "亚盛医药",
  "interview_topics": ["淋巴瘤"],
  "interview_focus": "关注新药研发进展、临床研究证据和耐药问题。",
  "language": "zh-CN"
}
```

不填写“淋巴瘤内科”。已掌握具体职务时可补充 `title`，否则由服务端检索核验；本例不预填未经调用方确认的职务。不会因为属于药企就要求提供临床执业或医院科室证明。

### 示例 3：药企研究人员，有真实部门

```json
{
  "name": "李华",
  "hospital": "示例生物医药有限公司",
  "department": "临床开发部",
  "title": "医学总监",
  "interview_topics": ["血液肿瘤临床试验设计"]
}
```

有部门就填写部门。“医学总监”是职务，不能填到 `department`。

### 示例 4：国内学会任职，没有医院职务

```json
{
  "name": "王宁",
  "hospital": "示例肿瘤学会",
  "department": "淋巴瘤专业委员会",
  "title": "委员",
  "interview_topics": ["淋巴瘤诊疗研究进展"]
}
```

填写真实的学会、分支组织及对应职务，无须补造医院身份。如果是学会本级理事，则省略 `department`，将 `title` 填为“理事”，不要默认属于某个专业委员会。

### 示例 5：国外学会理事，没有下属组织信息

```json
{
  "name": "Alex Morgan",
  "hospital": "Example Society for Hematology",
  "title": "Board Member",
  "interview_topics": ["Advances in lymphoma research"],
  "language": "zh-CN"
}
```

姓名、机构和职务可以保留原文，`language` 决定输出语言。无需为了中文输出把机构或职务强行翻译；不要把学会名称当作医院名称去寻找临床科室。

### 示例 6：研究所人员，有研究室或课题组

```json
{
  "name": "陈欣",
  "hospital": "示例生命科学研究所",
  "department": "肿瘤免疫课题组",
  "title": "研究员",
  "interview_topics": ["肿瘤免疫微环境"],
  "interview_focus": "关注机制研究、方法局限和转化验证。"
}
```

研究室、实验室和课题组均可作为 `department`。如果只知道研究所任职，省略该字段即可。“研究员”本身不代表在医院执业。

## 5. 常见错误与处理

| 情况 | 应如何处理 |
| --- | --- |
| 企业高管的科室被填为“淋巴瘤内科” | 如果只是采访议题，调用方清空科室、将“淋巴瘤”填入主题；服务端不静默把身份字段改成主题 |
| 不知道科室，填写“无／不详／不适用” | 省略 `department` 或传 `null` |
| `department` 填“教授／理事／首席医学官” | 移入 `title`；只有真实组织单元才能作为科室／部门／团队 |
| 只有姓名，不知道机构 | 本方案仍要求机构；请补充可用于识别人物的实际任职机构 |
| 一个主题很宽，如“医学” | 建议缩小到疾病、技术或研究议题，避免生成内容过于泛化 |
| 想采访企业经营战略、个人履历或学会内部管理 | 超出本期学术问答范围；不能仅靠填写 `interview_focus` 获得新的报告类型 |

身份核验与生成按以下边界处理：

- 姓名和机构有充分关联证据、且能排除同名混淆时，可以识别该人物；不因缺少医院科室、执业资料或论文而必然失败。
- 输入科室或职务只是线索。未查到附加任职不等于身份错误；可以保留限制说明，但不能写成已核实事实。若存在无法消除的人员或机构冲突，或科室冲突影响身份判断，不能直接忽略后继续生成。
- 新增主题只约束采访内容，不能作为“该人任职于该科室”或“该人已从事该领域研究”的证明。
- 旧调用方未传主题时，沿用已核实专业背景生成；不得从缺乏依据的输入自动编造专业领域。资料不足仍可能失败。
- 身份无法确认时，沿用现有失败状态和原因分类。现有 `needs_input` 用于已有的候选身份选择流程，本期不承诺通过它补填任意字段。修改输入后需使用新的幂等键创建任务；相同请求的网络重试沿用原键。

## 6. 结果如何理解

结果字段及版本沿用现有协议，但需放宽一项校验：`identity_resolution.matched_by` 允许无科室人物返回 `["institution"]`；其他匹配组合仍要求至少 2 项，不允许仅以科室或采访主题作为匹配依据。调用方如使用旧 JSON Schema 或自行检查数组长度，须同步更新；这不表示仅凭机构名称即可通过核验，人物与机构的关联仍须有证据支持。

输入回显中的 `doctor.hospital`、`doctor.department` 表示请求信息，**不等同于每个字段已被核实**。人物身份核验通过也不等于具备临床执业资格。

已核实任职使用现有 `profile.positions` 和带来源的 `profile.claims` 表达；资料缺失、任职未核实等情况使用 `source_coverage.limitations` 表达。调用方应展示这些限制说明，不要只显示“成功”后隐藏资料局限。

本期不新增逐字段核验结果结构。服务端须按实际证据填写 `matched_by`，无科室或科室未核实时不能标记为科室匹配。

仍提供专业背景与 5 组有来源支持的学术问答。问答中的参考回答不是受访者本人观点；输入主题不保证有足够证据生成全部期望内容，也不保证每个主题都被等量覆盖。

## 7. 服务端可行性与上线前提

**服务端复用现有 agent 架构，已完成并发布程序校验和数据传递的必要调整。** 下表说明实现范围；人物身份与内容质量仍取决于可核验的证据。

| 环节 | 必要改造 |
| --- | --- |
| 接口解析与输入类型 | 修正平铺正文重复校验；接受科室缺省及两个新增字段；已有请求写法保持兼容；拒绝未知字段的规则保留 |
| 身份调查与复核 | 当前结构校验强制要求科室及科室证据；改为按实际提供并核实的身份信息校验，允许无科室；继续要求人物与机构关联证据 |
| 研究生成与事实复核 | 将主题和重点传到生成及复核阶段；保持 5 组学术问答与来源校验；不把采访需求当人物事实 |
| 结果及文件生成 | 去除固定的“机构和科室都匹配”标记；允许只有机构匹配项；无科室时正确生成身份描述和关键词；展示标签采用“所属机构”“科室／部门／团队” |
| 存储、幂等及任务恢复 | 复用现有输入 JSON 存储；新字段参与完整请求指纹与生成阶段恢复校验；不因主题变化把同一人物当成新身份；兼容旧输入及旧任务状态 |

无需为本期增加多任职数组、机构类型枚举、组织层级对象、任期管理、新版结果结构或新接口路径。是否需要额外数据库迁移，应以实现时的兼容验证为准，不预设新建业务表。

上线顺序：先发布可处理新旧输入的 worker，再开放网关新字段，最后由调用方启用新表单。回退时先停止接收新格式，并处理完相关任务或保留兼容 worker，避免旧 worker 读取新任务。

身份调查仍需在既有预算内完成：无科室不再反复寻找医院科室证明；证据不足时应给出明确限制或失败原因，避免无新证据的重复核验。增加时间上限不能保证成功，120 秒也不是整个异步任务的完成时限。

本次新能力要求服务端启用身份 agent 和专业背景生成流程。旧流程不接收新增采访字段，worker 也不会静默忽略这些字段。实际发布会核对配置。既有任务并发、调用次数及人物配额限制继续生效。

首期联调至少覆盖：

1. 原有平铺、嵌套请求和幂等重试保持兼容；缺省新字段不改变旧请求的幂等判断。
2. 医院有科室、企业无部门、学会本级任职、研究所团队等真实样本均可进入正确流程。
3. 无科室请求不会被标记为“科室匹配”；未核实职务不会变成已验证事实。
4. 错误机构、同名人物及相互冲突的任职信息不会被宽松放行。
5. 修改主题会影响生成输入与恢复校验；不同主题不改变人物身份认定。
6. 任务重启恢复、旧结果读取、文件下载和限制说明展示正常。
