## 如何判定与修复

| 证据 | 处理方向 |
| --- | --- |
| Electron 与同机 curl 都卡在 DNS/TCP/TLS；换网络恢复 | 网络、DNS、代理或路由；按失败阶段处理 |
| curl 快速成功，Electron 网络事件卡住／复用旧请求 | Electron updater 会话、连接池及请求生命周期 |
| 网络在 12 秒之后成功，但控制器一直记 error | 期限与迟到结果处理；记录终态并明确是否采用过期结果 |
| 后续 check 只有 already in progress，没有新网络请求 | 前一检查未结束；实现可靠取消或有界恢复，避免继续等待同一挂起任务 |
| HTTP 已明确返回 4xx/5xx 或清单解析失败 | 更新源或清单问题；记录状态和 CF-Ray，按服务端证据处理 |

客户端改进优先补齐请求关联和终态观测，再实现能取消底层请求的截止机制，或按依赖支持能力隔离过期检查及恢复下一轮。不能只清掉外层 pending 就认为网络请求已结束。验收覆盖：慢响应、永久 pending、迟到成功、网络变化、休眠／恢复，以及超时后下一轮真正发起新检查且只有一个有效终态。超时长度应根据阶段耗时证据决定。
