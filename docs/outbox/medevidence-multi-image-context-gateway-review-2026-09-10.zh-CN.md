## 结论与当前状态

文档可作为联合改进的基础。现场因果和职责划分成立：12 张图片在进入上游前被拒绝，
压缩后 4 张图片请求的 HTTP 500 是后续独立故障；不能把两者合并为一个根因，也不能
将压缩成功、其他会话恢复或模型返回 stop 当作该 PPT 交付完成。

## 首批双方配合

### 1. 图片预算与专用错误恢复，优先实施

Desktop 在实际模型请求序列化前选择图片，覆盖工具产图、用户附件、读取文件、截图、
重试及压缩恢复。原图和已完成工具结果继续保存，只调整本轮模型看到的图片。
选择后刷新访问 URL，再校验最终实际发送的图片条目数。

Gateway 保持 8 张硬限制，返回结构化的图片限制类别、允许值、实际值和恢复建议。
推荐首版保留 HTTP 413 和既有 invalid_request，添加图片专用细分字段；若改用顶层
image_count_exceeded，必须先完成客户端兼容检查。具体字段仍待双方定稿，本文不将
任何拟议字段视为已上线合同。

**客户端必须先识别图片专用分类，再进入通用 413 处理。** 只在 Gateway 添加字段，
不会改变当前客户端直接触发全文压缩的行为。旧客户端仍走原恢复路径；新版应选图、
减图或分批，避免原样自动重发同一个超限请求。

数量、单图字节数、内联图片合计字节数、HTTP 请求体大小、文本 token 上下文分别报告。
当前内联单图和内联合计均限制为 20 MiB；资产单文件限制与 HTTP JSON 的字节数是不同
概念。完整数量只在请求体成功解析、全量计数后报告。HTTP 层提前拒绝时不能编造图片数。

### 2. 视觉有限恢复与终态合同，作为同一批交付

接受“同一 Gateway 请求最多两次实际模型调用”的方向，但实施需满足：

- 两次预算包含初次生成、工具参数纠错和故障重试。现有 NativeCallBudget 的约束目前
  仅通过文本 P0 路径接入，不能只给视觉入口增加一个重试循环。
- 同一视觉服务重试与切换备选服务分开实现。文本路径会排除已经尝试过的账号；直接
  照搬会把唯一 xAI 账号排除，仍然无法进行单服务重试。
- 使用内部失败分类判断恢复条件。当前上游 401/403 也映射为 upstream_unavailable，
  因此不能仅凭这个公开错误码或中文提示决定重试。
- 两次调用和等待共用原总期限；第二次只能使用剩余时间。429 必须处理等待要求并检查
  剩余期限，不应立即连续重试；不可恢复的认证、权限、格式、图片数量及权益错误不重放。
- 已交付正文、推理内容或工具调用后不透明重放；取消、断连、总期限到期后不新增调用。
  SSE 响应头、创建事件或 ping 不能单独作为业务内容已交付的证据。
- 最终失败时，HTTP JSON、Chat SSE 和 Responses SSE 均保留 request ID，按既有严格
  类型合同返回数字 retry_contract_version=1、布尔 automatic_retry_allowed=false。
  只发送一个失败终态，不再发送成功终态；成功结果不带停止标记。

停止原因应区分调用预算耗尽、剩余期限不足、已交付内容、取消及无可用服务。
“不能切换备选”不等于“不能重试同一服务”；“禁止客户端自动重试”也不意味着已经调用两次。

**兼容旧安装包是上线条件。** beta.38 不能仅凭当前源码合成测试认定已支持停止合同。
单请求最多两次不等于整个 Desktop 用户轮次最多两次。建议先验收支持合同的新客户端，
再按客户端能力／版本启用 Gateway 视觉重试，防止旧客户端叠加重试。

## 后续能力与需要补充的细节

1. **旧图恢复不能只保存临时 URL。** 需要稳定资产标识以及可恢复的原文件／内容引用，
   区分访问 URL 到期和资产本身到期。前者刷新 URL；后者需要从原件重新准备资产，
   或明确说明原件不可用。图片版本、hash 和已检查结论必须关联，不能沿用旧版检查结果。
2. **能力值尚未形成统一来源。** Gateway 请求解析和资产服务各有一份 8 张／20 MiB
   常量；Desktop 也硬编码并严格校验返回值等于 8 张／20 MiB。先统一来源并保持现有值，
   后续再设计可发现和版本兼容的能力合同。单独提高服务器数值可能导致客户端拒绝资产响应。
3. **一次请求结算和供应商尝试记录要分开理解。** 用户请求只形成一个终态、一次预留的
   完整结算；供应商多次调用各自保留状态和用量。现有汇总会合并尝试用量，不能直接推导为
   “第二跳零成本”或“所有失败尝试都不计费”。本轮不顺带改变计费规则。
4. **诊断避免重复计数。** 以最终 wire payload 图片条目数为准，另记来源／选入／排除数；
   关联会话、消息、轮次和 request ID，记录停止原因与内容交付状态。图片生成关联字段
   也应补齐。保留分类和摘要，不记录原始图片、带签名 URL 或完整用户材料。

## 联合验收顺序

1. 8 张历史加 4 张工具图片：客户端保存全部图片，最终模型输入不超过 8；直接发送
   12 张时 Gateway 在上游前返回准确的图片限制错误，上游调用数为零。
2. 修正为 4 张后原会话可继续；不无条件压缩全部文本，不重复执行已完成的生图或写文件。
3. 模拟首跳 500、第二跳成功和两跳失败：核对实际调用数、唯一终态、请求编号、用量及预留。
4. 覆盖已交付内容、取消、超时、429 等待超出剩余期限、工具纠错消耗预算、旧客户端行为。
5. 覆盖旧图点名重读、访问 URL 到期、资产到期、图片版本更新和超过 8 图的比较任务。
6. 完成真实安装包的原会话 PPT 流程；全部应检查页面完成分批检查，实际 pptx 存在且可打开。

首批不必等待完整的图片语义索引与自动审稿系统。先完成调用边界预算、图片错误合同，
再交付视觉有限恢复与客户端终态处理；图片索引和分批验收继续推进。
