# Gateway 超时诊断优化与 Desktop 配合建议

日期：2026-10-12。状态：Gateway 本地实现，尚未发布；本文不是已上线通知。

## Gateway 本次实现

- 管理端请求详情新增 `timeout_diagnostic`：分别记录触发来源、终止时输出阶段和最近收包情况。可区分总时限、响应头/响应体超时，以及仅推理、正文未完成、工具参数未完成等。历史证据缺失保留 `unknown`。
- 5/15 分钟运维窗口改按 `started_at + duration_ms` 推算的完成时间统计，避免运行十分钟的请求刚超时就已落出窗口。缺少耗时的旧记录回退开始时间，并计入 `missingDuration`。
- 增加模型调用专用统计，排除凭证查询、准入拒绝；超时率和模型 P95 排除用户取消。旧的全部事件统计仍保留。
- 活跃请求每 5 秒检查：300 秒仍未记录首个响应写入时提醒；超过截止时间 30 秒仍未清理时告警。同一请求同类日志只记录一次，结束即移除活跃告警。首次响应写入不是首个有效结果，也不证明客户端收到；本期不能检测已发首包后的所有停滞。
- 运维快照增加聚合告警：单次超时为 info；同一用户 30 分钟内至少 2 次为 warning；同一模型/运行通道 15 分钟至少 3 次、涉及至少 2 名用户为 warning，样本达到 20 次时还要求超时率至少 10%。阈值是初始运维默认值，须结合实际流量调整。
- 健康检查消费分类与聚合告警；活跃快照超过 20 秒或时间无效时提示证据过期，不据此断言当前请求未清理。

聚合告警由现有 `ops-snapshot`/健康检查调用时生成，不包含独立通知调度、持久化抑制或短信/IM 推送。活跃请求告警随服务定时输出日志。外部告警接入需按告警类型与对象去重、设置冷却和恢复通知；不要每次采集都推送。

自审补强：用户重复超时告警采用稳定的用户标识哈希，新增请求不会改变该告警 ID；路由信息缺失时保留单次/用户告警，不合并成通道故障。CLI 同样读取请求级终态分类，兼容没有 attempt 详情的记录；健康检查兼容旧快照和损坏的活跃告警字段。定时检查在服务 ready 后启动，关闭时清理。证据缺失、连接拒绝或缺少响应阶段时不强行判为连接超时/等待响应体。

公开 `upstream_timeout` 与 SSE 协议未变。本期未调整总超时、自动重试、切换上游或计费。管理端诊断不能直接作为 Desktop 公共接口使用。最近收到字节可能只是心跳；上游收到正文或工具参数也不等于已经交付客户端。不得向用户显示推理原文或未完成的工具参数。

SQLite 迁移 40 新增完成时间表达式索引，不改历史请求与计费记录；缺字段的精简历史库跳过该迁移。发布前须按现有发布流程评估实际数据库的建索引耗时和额外空间，备份后使用已提交、测试过的 main 制品发布并验证。此次未操作生产库。

## 可转发给 Desktop 的改进要求

请优先做以下三项，帮助用户理解等待并在失败后恢复：

1. **等待和取消**：显示本轮耗时、当前客户端可确认的阶段及取消入口。长等待可提示“处理时间较长，仍在等待结果，可继续等待或取消”；没有 Gateway 明确进度信号时，不宣称“模型正在推理”或显示虚假完成百分比。区分请求已建立、收到心跳、收到可用正文、工具开始/结束。
2. **超时恢复**：失败后保留用户输入、已展示内容和已生成文件，显示简明提示与复制诊断编号入口。根据已有 model-call recovery 协议先核对原请求状态/可恢复结果，再提供手动重试；不要因断线或超时直接重复执行有副作用的工具。对真实服务端截止超时，不把已结束请求显示成仍可继续等待。
3. **`document_asset` 可定位错误**：客户端采集时保留白名单结构字段，如稳定 `error_code`、`stage`、错误类型、脱敏后的简短原因，以及 session/message/tool-call/gateway-request 关联 ID。区分输入校验、资源定位、读取、解析、渲染、保存等实际阶段，不把所有错误压成 `Operation failed`。对用户展示安全提示；诊断上传过滤密钥、完整路径、文档内容和原始堆栈。Gateway 无法从已脱敏的历史记录还原原始异常；该问题根因仍需故障客户端证据，不能据现有通用错误指定某个渲染库故障。

后续联合能力：若要展示“上游仍有进展/只在推理/工具准备中”，需先约定受鉴权保护的最小进度协议、能力协商、刷新频率和失效语义，再由 Gateway 增加实时进度采样。当前终态统计与管理端接口不能提供该实时能力。

## 联合验收场景

- 上游持续推理直至总截止：诊断为总时限 + 仅推理；客户端不显示网络断线，不丢输入。
- 上游发工具参数中途截止：工具未校验完成不得执行，也不得自动重复触发工具。
- 响应头/响应体停滞：来源和阶段分开记录，心跳不作为可用结果。
- 用户取消：快速退出等待，记录取消，排除超时率；已完成副作用不重放。
- `document_asset` 不同阶段失败：产生可区分错误码与完整关联 ID，上传中无敏感原文。
- 完成时间窗口、低流量与高流量阈值、过期快照和旧版缺字段兼容。

预期收益：Gateway 本期主要缩短发现与定位时间；Desktop 完成上述配合后，可直接改善等待反馈、失败后恢复和问题反馈质量。单靠分类与告警不会降低实际超时率，也不会修复文档生成根因。
