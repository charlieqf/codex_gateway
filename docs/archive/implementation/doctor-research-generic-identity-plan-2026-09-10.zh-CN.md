# Doctor Research 通用身份发现改进方案（2026-09-10）

状态：局部设计草案，尚未实施或发布。整体架构、改造顺序与验收以 [整体设计审查](doctor-research-design-review-2026-09-10.zh-CN.md) 为准；本文保留身份发现的细节，不能用两个固定模型节点替代完整 Agent 研究循环。依据为 [去预置与八例盲测审计](../operations/doctor-research-generalization-audit-2026-09-10.zh-CN.md)。目标是在仅输入姓名、机构、科室时，对未见过的机构和医生也能完成有来源依据的识别；保持错人、错机构和历史任职的防护。

## 核心决策

将候选发现与身份确认拆开。规则承担输入规范化、预算、实际抓取、来源定位和引用完整性检查；模型承担受约束的跨语言查询规划及证据语义判断。模型生成的机构译名只用于找候选，不能直接成为身份事实；身份判断必须引用当次抓取的具体资料。

Agent 应能根据读取结果重新规划、导航和补证，不限定为一次规划、一次核验。精确标识符与经过验证的缓存可作快路径；存在人物错配风险的窗口匹配不能作为最终放行捷径。模型和工具调用均经过统一的预算、持久化与遥测，不要求每个网页分别进行长推理。

## 1. 请求字段先转为候选表达

保留用户原文，分开记录机构实体、临床专业、组织层级和行政职务。统一 Unicode、空白和连字符，保留姓名原字形；跨文字的姓名变体只作为候选，不自行认定为同一人。机构的原文、译名、简称和上级组织分别记录，不把大学、附属医院及医疗集团视为可互换的名称。

已有可靠词汇或当次证据足够时不用模型；其余请求可以产生少量机构和科室译名候选。模型输出中不允许提供个人履历、捏造主页或将译名标为已核实。仅含汉字不能决定国家或检索语言，日文姓名也包含汉字。

机构登记资料可以提供辅助。ROR 的公开记录包含多语言名称、别名、官网和位置，可作为通用机构解析来源；它定位于研究机构，不能假定覆盖全部医院、企业及协会，更不能用机构登记证明个人任职。未命中时继续网页发现，不能新造一个必须过的登记门槛。[ROR 说明](https://ror.org/about/faqs/)、[API](https://ror.readme.io/docs/rest-api)

## 2. 按当前缺少的证据选择搜索

初轮查询可与输入解析并发，避免所有请求先等模型。规划器从原始姓名加机构、姓名加专业、姓名加机构原文等组合中选择有限的互补查询；少见姓名可用姓名单独查询补充发现。适配器接收显式查询计划，不再仅凭内部 institutionHost 隐式改变所有补搜。

每轮评估候选是否含目标姓名、机构线索和人员页/科室目录线索，再决定下一步。没有候选时改变语言或约束；有候选但只到首页时进入目录；已得到文本但机构未确认时补机构证据。域名限定查询必须保留跨域补搜出口，不能因搜到中文招生站而永久锁定该站。

搜索结果标题和摘要只用于候选排序，不作为最终身份依据；目录摘要未包含完整姓名时，不应立即丢弃有明确机构及科室线索的结果。同名歌手、同名不同机构及镜像转载应在排序和确认阶段分别处理。

保持总请求、字节和截止时间上限。初版在既有预算内重分配查询和抓取额度，给后续纠偏保留额度；同时更新 Worker 配置的最坏情况预留校验。不能只增加循环次数、提高来源数量后忽略重试预算。

## 3. 官网发现应能进入人员目录

将“允许抓取”与“已证明来源属于目标机构”分开。继续使用现有安全 HTTP 抓取；官网归属由机构登记、机构介绍、可核验的官网关系和链接等证据确认，不只依赖域名后缀、页面自称官方或中文标题精确出现。

网页提取保留真实链接、标题层级、个人卡片和表格行。除领导页外，支持从页面中发现人员、专家、科室、门诊排班等目录。只跟随实际出现的链接，在限定深度和抓取预算内导航，不根据姓名拼接任何网站的 URL 模板。

大学中文站、医学院站、医院站可以成为不同候选；只有来源支持关系时才连接它们。不能把一所大学的所有附属医院或某医疗集团的所有院区自动合并。

## 4. 身份确认由可定位的证据支持

将候选页面的有限文本、结构和已核实的机构资料提供给研究 Agent，根据证据关系确认身份或决定继续补证。输出应包含：

- 姓名是否对应、机构关系是否支持、专业是否对应，分别为支持、冲突或不足。
- 每项依据的 sourceId、原文片段及片段位置；系统检查片段确实存在于抓取文本中。
- 机构及专业的原文表达和匹配关系，而非仅一个自报“置信度”。
- 任职或关联的时间范围，以及来源是当前目录还是历史报道。

模型只能引用已提供的来源，不能生成新 URL；网页内容只是证据，不是可执行指令。原文片段存在只是必要条件，仍需评估语义和人物归属。官网个人页或目录记录可以直接支持身份；第三方材料需要核查出处和独立印证，两个转载同一新闻的网页不算两个独立来源。

特别防止把列表中甲的姓名、乙的科室和页面页脚的机构拼成一个人。应优先使用同一人员卡片、表格行和所属科室标题的关系，不能继续把“附近 5000 字出现这些词”当成充分的关系证明。

历史关联与现职分开输出。名字相同但机构或专业冲突时保留冲突；证据不足时不能自动按用户输入补齐任职。本人论文的作者归属继续单独核实，医生身份确认不等于论文作者身份确认。

## 5. 状态、时延和缓存

身份结果区分已确认、存在多个候选、证据不足和外部访问失败。已有 needs_input 可供真正的歧义使用；搜索超时不能伪装成“请用户确认身份”。失败诊断应能指出缺少的是姓名、机构、专业、来源归属还是可读取正文。

完整研究只使用已确认的身份事实。可以保存候选和已取得的资料供展示或恢复，但不能用完整报告的成功状态包装未确认身份或文献不足。先记录兼容的后端诊断；候选选择和分阶段进度展示再与客户端契约配合，不把后端修复卡在 UI 改造上。

用户规定完整服务耗时不超过 5 分钟为优秀，5–8 分钟可接受，超过 8 分钟需要调查原因；该调查线不等于强制终止线。按此目标分配身份阶段预算，并为后续研究、生成及结果保存留时间；先排序再有限并发抓取，证据充分就取消多余请求。不能以几十秒提前拒绝身份作为性能优化。模型调用需实测延迟，重试按已完成的计划和证据恢复，避免重复支付解析成本。

生产可复用自然请求产生、带来源/时间/版本的机构解析与网页缓存；过期或冲突时重新核查，不把超时缓存为“此人不存在”。盲测禁用应用缓存和 SerpAPI 缓存，生产不为测试预热任何身份资料。SerpAPI 的 no_cache 控制供应商搜索缓存，不等于控制 Google 索引或其他上游缓存。[SerpAPI 文档](https://serpapi.com/search-api)

搜索供应商故障再考虑配置好的独立备用提供商；只在同一个 SerpAPI 中换引擎不构成独立提供商容灾。此次多数失败已有 HTTP 200，改提供商不应替代跨语言发现和身份核验改进。

## 6. 实现顺序

第一批：从 workflow.ts 拆出查询计划、候选收集和身份核验模块；修复补搜域名锁定、目录候选过滤及真实链接导航；保留分阶段诊断和脱敏候选元数据，明确“搜索未返回”和“返回后被过滤”的区别。

第二批：接入有预算且可恢复的 Agent 研究循环，更新 WorkflowContext 允许的阶段、模型调用与时间预算、Worker 重试和遥测；仅对证据有效的缓存等保留快路径。机构解析来源是可替换接口，不要求先建全世界机构数据库。

第三批：实现可解释状态、缓存和增量恢复；分别验收医生身份、本人论文归属及研究报告质量。根据实际失败分布再决定增加独立搜索提供商或更重的页面渲染能力。

## 7. 验收与防止再次对案例定制

原六例、王永生及已揭示八例只作为回归集，不再称为盲测。开发和测试资料与运行包隔离；运行代码不得导入这些人的名单、机构专用别名、个人页或答案。通用公共词表/登记数据需固定版本并披露，不能把本批机构新增条目伪装成公共基础数据。

当前 SerpAPI 额度有限，本轮不执行新的联网批测，先用已有资料重放及离线反例验证。此前首轮 30–50 个联网正例的建议不作为本轮计划。额度允许后的新版本验收再独立抽取未见过的人和机构，先固定整批实际搜索请求上限，包含全部重试与重排。另设同名不同人、错误机构/专业、历史机构、译名变化、空格/标点、目录多人的反例与变体测试。正例与反例分别计分，身份确认和完整报告分别计分。

预先固定样本、运行次数、预算和人工核验规则，保留全部失败与自然重试，不从重复执行中挑最好一次。小样本全通过也不能等同于总体无误认。

采用以下指标判断改动：正确身份通过率、错误身份接受率、正确来源进入候选的比例、候选被正确核验的比例、身份阶段 P50/P95、总耗时和每例调用成本。快但证据不足不计通过；生成了文件也不自动计为报告质量合格。

还需做同版本的组件对照：规则快路径、增加查询规划、再增加证据核验各自贡献多少。记录冻结的原始搜索候选及抓取材料用于离线复核，同时用新的实时盲测检验完整流程；离线重放不得当作实时无缓存性能。

最终发布前应通过实际 Worker 的重排、超时后下一任务恢复、公网准入和产物校验；上一轮隔离的单次工作流探针不能替代这些检查。
