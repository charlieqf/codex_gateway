## 已核对的代码路径

1. `packages/research-agent/src/workflow.ts` 的 `discoverIdentityEvidence` 在调用模型前执行 `searchOfficialSources`。
2. `packages/research-agent/src/live-adapters.ts:724` 的 `searchSerpApi` 使用最多两次请求，线上 `RESEARCH_ADAPTER_TIMEOUT_MS=20000`，重试间隔 250 ms。
3. `requestJsonWithRetry` 原本保留 `TimeoutError`、`ResearchExternalServiceError` 等类型。
4. `searchSerpApi` 的 catch 仅保留调用方 abort 和 `ResearchHttpError`；其余异常被替换为普通 `Error("Official web search request failed.")`。
5. workflow 无法再走超时/传输错误分支，落入通用 `upstream_unavailable / retryable=false`，未指定 request 级别的故障范围。
6. `apps/research-worker/src/runtime.ts:335` 将未指定范围记为 service；任务失败后调用 `stopForDependencyFailure()`，触发 worker 退出。

运行中 worker 的编译后 `live-adapters.js` 已直接确认包含该包装逻辑；并非仅根据本地源码推断。

还有一处需要一并修复：workflow 的独立 `TimeoutError` 分支使用 `modelCallsStarted === 1` 决定是否重试，身份检索阶段为 0。即使保留了超时类型，这个阶段目前也不会自动重排任务；应明确早期检索失败的有限重试策略。
