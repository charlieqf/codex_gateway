publicModel.pool!.members.every(
  (member) => member.runtime === "tencent" || member.runtime === "tiankuan"

TokenSwitch 的存在使 `goldencodeRequestFailover` 为 false。已核对部署目录与本地该源码 SHA-256 相同：`94a054f9f19082759073ad89637ef132af62a02f4a8596f62c1d6f0506beb842`。

离线复现使用本地 Gateway 构建、内存 SQLite、回环 HTTP 模拟上游；第一家返回 503，第二家可以正常返回工具调用。没有访问真实供应商、没有生产写入。

工具参数修复在业务请求中共触发 13 次，12 次恢复成功，1 次仍失败。上述 TokenSwitch 问题不应通过放行非法 JSON 处理；供应商排查时需按请求时间、两次尝试及参数诊断定位，并回传脱敏的请求追踪与参数生成原因。通过标准是相同工具 schema 下参数可解析且符合 schema，不仅是 HTTP 200。

腾讯 900 秒请求应请供应商结合上游请求 ID 检查停流、完成标记与连接关闭记录；回传首包、最后数据块、结束原因即可，不需要用户对话原文。已有少量内容的请求不能盲目重复执行，也不应直接延长 900 秒预算。

本地输出截断可由调用方分段生成、继续生成，或在本地模型 8,192 输出上限和剩余上下文允许时提高请求输出上限。验收应同时检查结束原因为正常完成及目标内容完整。

## 7. 结论边界与证据
