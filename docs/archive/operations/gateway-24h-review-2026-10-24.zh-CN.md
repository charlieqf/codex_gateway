## 3. 两次会议工具参数校验失败

- `req-cb2582af-4ce0-43de-a24c-a275917044f5`：北京时间 10-23 17:42:50，13.4 秒。
- `req-213886cd-4250-4617-b39f-64f595d91cd2`：北京时间 10-23 17:43:07，14.1 秒。

均为 TokenSwitch GLM-5.3、low 推理、工具 `meeting_pack_submit_people`。原始响应及一次自动修复均返回 HTTP 200，但工具参数不满足声明：`expectedRevision` 应为 integer、`people` 应为 array、`complete` 应为 boolean。**JSON 本身可解析，问题是类型不符。** Gateway 的 AJV 校验拒绝执行，之后同账户模型请求恢复成功。

工具维护方应按这两个 request_id 核对实际发送的 schema 与返回参数的三个类型，检查是否重复 JSON 编码，以及模型是否把对象整体输出成字符串。最小回传材料为 schema 片段、三个字段的实际类型和 request_id，无需会话原文。若 schema 正确而模型持续输出错误类型，Gateway 的修复提示应明确字段路径及目标类型，并添加这组类型组合的回归样例。验收需保证参数符合 schema、业务工具仅执行一次，不能用放宽校验掩盖问题。

## 4. 一次图片生成触发 GPU 安全停止

`req-21179949-f341-455c-8b5e-171e9186cbc2`，北京时间 10-23 19:37:36 至 19:38:47，71.4 秒，公网返回 HTTP 500。

检查时池内 2 个 worker ready，队列和活跃任务均为 0，未发现重启；GPU 温度为 39℃、44℃，只是检查时快照。图片 fallback 当前关闭，符合既有配置。

改进应保留安全停止，把日志拆分为 `thermal_limit` 与 `gpu_monitor_failed`，记录温度、阈值、监测错误类别、worker/job 与 Gateway request_id。若再次确认过热，再检查散热和负载；不应直接提高温度阈值。此故障已自然恢复，无需为本次检查重启或重放用户图片。
