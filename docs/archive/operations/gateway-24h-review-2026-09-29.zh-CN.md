该客户端没有留下新协议回执。应优先接入稳定 Call ID、查询恢复、完成结果复用；对已收到 request ID 的调用，不能仅因本地流消费失败就重新生成。并检查单次调用无进展期限、进程挂起/休眠恢复和传输终态。Gateway 已完成与 Nginx 200 不能证明客户端成功消费响应；底层断点需客户端机器证据，不能仅凭服务器日志判定是休眠或某种网络故障。

### 2. 诊断上传：56 次 429，并出现日预算耗尽后的观测缺口

诊断端点：201=7,883，幂等成功 200=8，429=56，切换期 502=7。

- **52 次 429 集中在 beta.78 关联流量**，12:41–12:42 UTC。服务器 12:41:41 提示分钟上限 60、Retry-After=19 秒；同一分钟内仍发生 45 次拒绝，首秒就有 9 次。是收到冷却信号后仍持续发送的队列行为；版本来自凭证与邻近已接受诊断的关联，不是读取了被拒绝请求体。
- **1 次日限流来自 beta.85**，10:15:40 UTC：2000/day 用满，Retry-After=49,460 秒（到 UTC 日界）。该凭据自发布重启后确有 2,000 条接受记录，此后至窗口结束没有新诊断，但该主体又发起 **45 次模型调用**。这形成真实观测缺口；没有持续请求并不等于后续没有问题。
- 另 3 次发生在 01:35–01:37 UTC，属于发布前。该旧容器日志已不在当前 docker logs 范围，故不对这三次的 limit_kind 作未经证实的推断。

客户端应升级旧队列，严格遵守凭据级全队列冷却，并主动节流、去重/聚合和保留终态事件。Gateway 应联合评估活跃任务的遥测预算与批量协议、日预算耗尽告警和重要事件保留机制。当前限流按配置执行；仅提高上限不能解决旧客户端连续重试。

### 4. 天宽单次 403：平台拒绝，不能直接断言 Key 失效

10:11:02 UTC 发起的 `req-7cda77ff-a489-40eb-aee0-56d270aab171`，30.224 秒后天宽返回 403。Gateway 分类 provider/http_auth/after_headers，对外为 upstream_unavailable；客户端 T:QVPR9MK2 最终报错。

10:12:08 起同平台已有连续成功请求，因此没有持续凭证失效证据。现有脱敏日志没有上游拒绝正文，无法区分鉴权、WAF 或供应商策略拒绝。应凭请求时间与请求标识向平台定位，不能据此直接更换 Key 或停用天宽。

当前 `canFailoverNativeError` 明确不对 401/403 切换平台（允许的是 402/408/429/5xx 等合格错误）；本笔仅一次尝试，与当前策略一致。是否为这类失败增加受控切换，需要单独评审错误分类与适用条件。

### 5. 本地模型输出截断：输出预算和工具生成问题

应改为分段生成/写入、控制单次工具参数规模，并结合模型能力设置输出预算；不应仅延长超时。

### 6. 客户端断开、图片和其他错误

- 10 次模型 client_aborted：腾讯 4、天宽 6，全部有取消请求与取消观察记录。8 次在相同 message 下存在 user_action/stop；其中部分时间有偏差，不能把全部 10 次都说成用户主动点击停止。2 次缺乏 stop 佐证：T:Q0ZV246H、T:T9Z4GKK4，需客户端/网络证据。

## 处理顺序

1. **客户端/Gateway 联调回执接入**：用真实客户端验证 Call ID 持久化、断网/挂起后查询恢复、同一步不重复执行；当前只有服务端自测证据。
2. **客户端遥测队列与 Gateway 预算联合修正**：淘汰 beta.78 的持续重试行为，同时处理 beta.85 日预算耗尽后无诊断的缺口。
3. **Gateway 发布排空与切流**：修复单容器重建空窗，并记录完整边缘错误和连接影响。
4. **供应商与工具生成专项**：定位天宽单次 403、评审该类错误的切换策略；处理本地模型长工具输出预算。

证据限制：Nginx 覆盖完整窗口；Gateway docker logs 仅保留当前容器发布后的部分，发布前使用持久请求事件及边缘日志补充。客户端 created_at 使用终端时钟，可能有偏差，应结合 request ID、received_at 和服务器时间。没有重放真实任务，也没有采集终端电源或网络跟踪。
